# URL 입력 후 일어나는 일

## 전체 흐름 개요

브라우저 주소창에 `https://www.example.com`을 입력하고 엔터를 누르면:

```
1. URL 파싱
2. DNS 조회 → IP 주소 획득
3. TCP 연결 (3-way handshake)
4. TLS 핸드셰이크 (HTTPS)
5. HTTP 요청 전송
6. 서버 처리 및 응답
7. 브라우저 렌더링
```

---

## 1. URL 파싱

브라우저가 URL을 구성 요소로 분해합니다.

```
https://www.example.com:443/path/page?query=value#section
  │          │          │     │          │         │
  │          │          │     │          │         └─ Fragment
  │          │          │     │          └─ Query String
  │          │          │     └─ Path
  │          │          └─ Port (HTTPS 기본 443)
  │          └─ Host (Domain)
  └─ Scheme (Protocol)
```

브라우저는 입력이 URL인지 검색어인지 판단합니다.

---

## 2. DNS 조회 (Domain Name System)

**도메인 이름을 IP 주소로 변환**합니다.

```
www.example.com → 93.184.216.34
```

**DNS 조회 순서:**

```
1. 브라우저 캐시 확인
2. OS 캐시 확인 (hosts 파일 포함)
3. 로컬 DNS 서버 (ISP)
4. 루트 DNS 서버 → TLD 서버 주소 반환
5. TLD DNS 서버 (.com) → 권한 서버 주소 반환
6. 권한 DNS 서버 → 실제 IP 반환
```

**DNS 질의 과정:**

```
사용자 PC          로컬 DNS           루트 DNS
    │                 │                  │
    │── 질의 ────────►│                  │
    │                 │── .com 어디? ───►│
    │                 │◄── TLD 주소 ─────│
    │                 │      
    │                 │     TLD DNS        권한 DNS
    │                 │── example.com? ──►│
    │                 │◄── 권한 서버 주소 ──│── IP? ──►│
    │                 │◄───────────────────────────────│
    │◄── IP 주소 ─────│
```

**DNS 레코드 타입:**

| 타입 | 설명 |
|------|------|
| A | 도메인 → IPv4 |
| AAAA | 도메인 → IPv6 |
| CNAME | 도메인 → 다른 도메인 (별칭) |
| MX | 메일 서버 |
| NS | 네임 서버 |

---

## 3. TCP 연결 (3-Way Handshake)

**신뢰할 수 있는 연결을 수립**합니다.

```
Client                              Server
   │                                   │
   │─────── SYN (seq=x) ─────────────►│
   │        "연결 요청"                  │
   │                                   │
   │◄───── SYN-ACK (seq=y, ack=x+1) ──│
   │        "확인, 저도 요청"             │
   │                                   │
   │─────── ACK (ack=y+1) ────────────►│
   │        "확인"                      │
   │                                   │
   │         연결 수립 완료               │
```

**각 단계:**
1. **SYN**: 클라이언트가 연결 요청, 초기 시퀀스 번호 전송
2. **SYN-ACK**: 서버가 수락, 자신의 시퀀스 번호와 클라이언트 확인
3. **ACK**: 클라이언트가 서버 확인, 연결 완료

**TCP 특징:** 신뢰성, 순서 보장, 흐름 제어, 혼잡 제어

---

## 4. TLS 핸드셰이크 (HTTPS)

**암호화된 보안 연결을 수립**합니다.

```
Client                                   Server
   │                                        │
   │──── Client Hello ────────────────────►│
   │     (지원 암호화 방식, 랜덤 값)            │
   │                                        │
   │◄─── Server Hello + Certificate ───────│
   │     (선택된 암호화, 인증서)               │
   │                                        │
   │──── Key Exchange ────────────────────►│
   │     (Pre-Master Secret)                │
   │                                        │
   │◄─────────── Finished ─────────────────│
   │                                        │
   │         암호화 통신 시작                  │
```

**핵심 과정:**
1. **암호화 협상**: 암호화 방식 선택
2. **인증서 검증**: CA 서명 확인
3. **키 교환**: 대칭키 생성용 비밀값 교환
4. **세션 키 생성**: 이후 통신 암호화

---

## 5. HTTP 요청

**클라이언트가 서버에 리소스를 요청**합니다.

```http
GET /path/page HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0 ...
Accept: text/html,application/xhtml+xml
Accept-Encoding: gzip, deflate, br
Connection: keep-alive
Cookie: session_id=abc123
```

**HTTP 메서드:**

| 메서드 | 설명 | 멱등성 |
|--------|------|--------|
| GET | 리소스 조회 | ✓ |
| POST | 리소스 생성 | ✗ |
| PUT | 전체 수정 | ✓ |
| PATCH | 부분 수정 | ✗ |
| DELETE | 삭제 | ✓ |

---

## 6. 서버 처리 및 응답

**서버가 요청을 처리하고 응답을 반환**합니다.

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 1234
Cache-Control: max-age=3600

<!DOCTYPE html>
<html>...</html>
```

**HTTP 상태 코드:**

| 범위 | 의미 | 예시 |
|------|------|------|
| 2xx | 성공 | 200 OK, 201 Created |
| 3xx | 리다이렉션 | 301 Moved, 304 Not Modified |
| 4xx | 클라이언트 오류 | 400 Bad Request, 404 Not Found |
| 5xx | 서버 오류 | 500 Internal Error, 503 Unavailable |

---

## 7. 브라우저 렌더링

**서버 응답을 화면에 표시**합니다.

```
HTML 파싱 → DOM 트리
                    ├──► Render Tree → Layout → Paint
CSS 파싱 → CSSOM 트리
```

1. **HTML 파싱**: DOM 트리 생성
2. **CSS 파싱**: CSSOM 트리 생성
3. **Render Tree**: DOM + CSSOM 결합
4. **Layout**: 크기/위치 계산
5. **Paint**: 픽셀로 그리기

## 연결 종료 (4-Way Handshake)

```
Client                              Server
   │                                   │
   │─────── FIN ─────────────────────►│
   │◄────── ACK ──────────────────────│
   │◄────── FIN ──────────────────────│
   │─────── ACK ─────────────────────►│
   │         연결 종료                   │
```

---

## HTTP 버전별 차이

| 버전 | 특징 |
|------|------|
| HTTP/1.0 | 요청마다 새 연결 |
| HTTP/1.1 | Keep-Alive, 파이프라이닝 |
| HTTP/2 | 멀티플렉싱, 헤더 압축, 서버 푸시 |
| HTTP/3 | QUIC (UDP), 빠른 연결, HOL 블로킹 해결 |

```
HTTP/1.1:              HTTP/2:
요청1 ──►              요청1 ──┐
응답1 ◄──              요청2 ──┼──► 하나의 연결
요청2 ──►              요청3 ──┘
응답2 ◄──              응답들 ◄──
(순차적)               (병렬)
```

---

## TCP vs UDP

| 구분 | TCP | UDP |
|------|-----|-----|
| 연결 | 연결 지향 (3-way handshake) | 비연결 |
| 신뢰성 | 보장 (재전송) | 보장 안 함 |
| 순서 | 보장 | 보장 안 함 |
| 속도 | 느림 | 빠름 |
| 용도 | HTTP, FTP, 이메일 | DNS, 스트리밍, 게임 |

## 면접 예상 질문

**Q. URL 입력 후 화면이 나타나기까지 과정?**

URL 파싱 → DNS 조회(도메인→IP) → TCP 3-way handshake → TLS 핸드셰이크(HTTPS) → HTTP 요청 → 서버 응답 → 브라우저 렌더링 순서입니다.

**Q. DNS 조회 과정?**

브라우저 캐시 → OS 캐시 → 로컬 DNS 서버 순으로 확인합니다. 없으면 루트 DNS → TLD DNS → 권한 DNS 서버로 재귀적 질의하여 IP를 획득합니다.

**Q. TCP 3-way handshake란?**

신뢰할 수 있는 연결을 수립하는 과정입니다. SYN → SYN-ACK → ACK 순서로 양쪽이 송수신 준비가 되었음을 확인합니다.

**Q. HTTPS가 HTTP와 다른 점?**

TLS/SSL로 암호화됩니다. TCP 연결 후 TLS 핸드셰이크로 암호화 키를 교환하고, 이후 모든 통신이 암호화되어 도청/변조/위장을 방지합니다.

**Q. HTTP/2의 장점?**

멀티플렉싱(하나의 연결에서 여러 요청 동시 처리), 헤더 압축(HPACK), 서버 푸시를 지원합니다. HTTP/1.1의 HOL 블로킹을 해결합니다.

**Q. TCP와 UDP의 차이?**

TCP는 연결 지향, 신뢰성/순서 보장, 느림. UDP는 비연결, 보장 없음, 빠름. HTTP는 TCP, DNS/스트리밍은 UDP를 주로 사용합니다.
