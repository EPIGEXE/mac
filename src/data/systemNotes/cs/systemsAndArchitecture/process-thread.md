# 프로세스와 스레드

## 프로세스 (Process)

**실행 중인 프로그램의 인스턴스**입니다. 운영체제로부터 독립적인 메모리 공간과 시스템 자원을 할당받습니다.

프로그램은 디스크에 저장된 정적인 코드이고, 프로세스는 이 프로그램이 메모리에 로드되어 실행되는 동적인 상태입니다.

**프로세스 메모리 구조:**

```
┌─────────────────┐ 높은 주소
│      Stack      │ ← 지역 변수, 함수 호출 정보
├─────────────────┤
│        ↓        │
│                 │
│        ↑        │
├─────────────────┤
│       Heap      │ ← 동적 할당 메모리 (new, malloc)
├─────────────────┤
│       BSS       │ ← 초기화되지 않은 전역/정적 변수
├─────────────────┤
│       Data      │ ← 초기화된 전역/정적 변수
├─────────────────┤
│       Code      │ ← 실행할 프로그램 코드
└─────────────────┘ 낮은 주소
```

**프로세스가 가지는 것:**
- 독립적인 메모리 공간 (Code, Data, Heap, Stack)
- CPU 레지스터 상태
- 프로세스 ID (PID)
- 파일 디스크립터
- 프로세스 상태 (실행, 대기, 준비 등)

---

## 스레드 (Thread)

**프로세스 내에서 실행되는 흐름의 단위**입니다. 하나의 프로세스는 최소 하나의 스레드(메인 스레드)를 가지며, 여러 스레드가 존재할 수 있습니다.

**스레드 메모리 구조:**

```
┌─────────────────────────────────────┐
│            프로세스                   │
│  ┌─────────────────────────────┐   │
│  │   Code, Data, Heap (공유)    │   │
│  └─────────────────────────────┘   │
│                                     │
│  ┌────────┐ ┌────────┐ ┌────────┐  │
│  │ Stack1 │ │ Stack2 │ │ Stack3 │  │
│  │Thread1 │ │Thread2 │ │Thread3 │  │
│  └────────┘ └────────┘ └────────┘  │
└─────────────────────────────────────┘
```

**스레드가 가지는 것 (개별):**
- 스레드 ID
- 프로그램 카운터 (PC)
- 레지스터 집합
- 스택

**스레드가 공유하는 것 (프로세스 내):**
- 코드 영역
- 데이터 영역 (전역 변수)
- 힙 영역
- 파일 디스크립터
- 시그널 핸들러

---

## 프로세스 vs 스레드 비교

| 구분 | 프로세스 | 스레드 |
|------|---------|--------|
| **정의** | 실행 중인 프로그램 | 프로세스 내 실행 단위 |
| **메모리** | 독립적인 메모리 공간 | 프로세스 메모리 공유 (스택만 독립) |
| **생성 비용** | 높음 (메모리 할당, 복사) | 낮음 (스택만 할당) |
| **컨텍스트 스위칭** | 비용 높음 (메모리 주소 공간 전환) | 비용 낮음 (같은 주소 공간) |
| **통신** | IPC 필요 (파이프, 소켓, 공유 메모리) | 공유 메모리로 직접 통신 |
| **안정성** | 한 프로세스 오류가 다른 프로세스에 영향 없음 | 한 스레드 오류가 전체 프로세스에 영향 |
| **동기화** | 상대적으로 덜 필요 | 공유 자원 동기화 필수 |

## 컨텍스트 스위칭 (Context Switching)

**CPU가 한 작업에서 다른 작업으로 전환할 때 현재 상태를 저장하고 새 상태를 로드하는 과정**입니다.

**프로세스 컨텍스트 스위칭:**
1. 현재 프로세스 상태(레지스터, PC, 메모리 맵) 저장
2. PCB(Process Control Block)에 저장
3. 새 프로세스의 PCB에서 상태 로드
4. 메모리 주소 공간 전환 (TLB 플러시 등)
5. 새 프로세스 실행

**스레드 컨텍스트 스위칭:**
1. 현재 스레드 상태(레지스터, PC, 스택 포인터) 저장
2. TCB(Thread Control Block)에 저장
3. 새 스레드의 TCB에서 상태 로드
4. 새 스레드 실행 (메모리 주소 공간은 그대로)

스레드는 메모리 공간을 공유하므로 주소 공간 전환이 필요 없어 오버헤드가 적습니다.

## 멀티프로세스 vs 멀티스레드

**멀티프로세스:**

여러 프로세스가 동시에 실행됩니다. 각 프로세스는 독립적인 메모리를 가집니다.

```
┌─────────┐  ┌─────────┐  ┌─────────┐
│Process 1│  │Process 2│  │Process 3│
│ [메모리] │  │ [메모리] │  │ [메모리] │
└─────────┘  └─────────┘  └─────────┘
     ↑            ↑            ↑
     └────────────┼────────────┘
                 IPC
```

장점:
- 한 프로세스 오류가 다른 프로세스에 영향 없음
- 메모리 침범 불가로 안정적

단점:
- 메모리 사용량 많음
- 컨텍스트 스위칭 비용 높음
- IPC 오버헤드

**멀티스레드:**

하나의 프로세스 내에서 여러 스레드가 동시에 실행됩니다.

```
┌─────────────────────────┐
│        Process          │
│  ┌───┐ ┌───┐ ┌───┐     │
│  │ T1│ │ T2│ │ T3│     │
│  └───┘ └───┘ └───┘     │
│    ↑     ↑     ↑       │
│    └─────┼─────┘       │
│      공유 메모리         │
└─────────────────────────┘
```

장점:
- 메모리 공유로 자원 효율적
- 컨텍스트 스위칭 비용 낮음
- 스레드 간 통신 빠름

단점:
- 한 스레드 오류가 전체 프로세스 영향
- 공유 자원 동기화 필요 (복잡성 증가)
- 디버깅 어려움

## 동기화 문제

멀티스레드에서 공유 자원에 동시 접근 시 발생하는 문제들입니다.

**경쟁 상태 (Race Condition):**

여러 스레드가 공유 자원에 동시 접근하여 결과가 실행 순서에 따라 달라지는 상황입니다.

```javascript
// 두 스레드가 동시에 실행하면?
let counter = 0;

// Thread 1        // Thread 2
// counter++       // counter++
// 예상: 2, 실제: 1 또는 2 (비결정적)
```

**교착 상태 (Deadlock):**

두 개 이상의 스레드가 서로 상대방이 가진 자원을 기다리며 무한히 대기하는 상황입니다.

```
Thread 1: Lock A 획득 → Lock B 대기
Thread 2: Lock B 획득 → Lock A 대기
→ 둘 다 영원히 대기
```

교착 상태 발생 조건 (4가지 모두 만족 시):
- **상호 배제**: 자원은 한 번에 하나의 스레드만 사용
- **점유 대기**: 자원을 가진 채 다른 자원 대기
- **비선점**: 다른 스레드의 자원을 강제로 빼앗을 수 없음
- **순환 대기**: 스레드들이 순환 형태로 자원 대기

**동기화 기법:**

| 기법 | 설명 |
|------|------|
| **뮤텍스 (Mutex)** | 한 번에 하나의 스레드만 임계 영역 진입 |
| **세마포어 (Semaphore)** | 지정된 수만큼의 스레드가 동시 접근 가능 |
| **모니터 (Monitor)** | 뮤텍스 + 조건 변수 (Java synchronized) |
| **원자적 연산** | 중단 불가능한 단일 연산 (Atomic) |

```javascript
// JavaScript는 싱글 스레드지만, Web Worker 사용 시
// SharedArrayBuffer와 Atomics로 동기화

// 원자적 연산 예시
Atomics.add(sharedArray, index, value);
Atomics.compareExchange(sharedArray, index, expected, replacement);
```

## 프로세스 상태와 스케줄링

**프로세스 상태:**

```
        생성 (New)
            │
            ▼
  ┌───── 준비 (Ready) ◄─────┐
  │         │               │
  │    스케줄링              │ 인터럽트/
  │         ▼               │ 타임아웃
  │     실행 (Running) ─────┘
  │         │
  │    I/O 요청 등
  │         ▼
  └──► 대기 (Waiting) ───► I/O 완료 ───► 준비
            │
            ▼
        종료 (Terminated)
```

**CPU 스케줄링 알고리즘:**

| 알고리즘 | 설명 | 특징 |
|---------|------|------|
| FCFS | 먼저 온 순서대로 | 비선점, 호위 효과 |
| SJF | 짧은 작업 우선 | 평균 대기 시간 최소, 기아 가능 |
| Round Robin | 시간 할당량(Quantum) 순환 | 선점, 시분할 시스템 |
| Priority | 우선순위 기반 | 기아 문제 → 에이징으로 해결 |
| Multilevel Queue | 여러 큐로 분류 | 포그라운드/백그라운드 분리 |

## 커널 스레드 vs 유저 스레드

**커널 스레드:**
- 운영체제가 직접 관리
- 스케줄링 단위
- 생성/관리 비용 높음
- 한 스레드 블로킹해도 다른 스레드 실행 가능

**유저 스레드:**
- 사용자 공간 라이브러리가 관리
- 커널은 존재를 모름
- 생성/전환 빠름
- 한 스레드 블로킹 시 전체 프로세스 블로킹

**매핑 모델:**

| 모델 | 설명 |
|------|------|
| N:1 | 여러 유저 스레드 → 하나의 커널 스레드 |
| 1:1 | 유저 스레드 하나당 커널 스레드 하나 (Linux, Windows) |
| M:N | 여러 유저 스레드 → 여러 커널 스레드 |

## IPC (Inter-Process Communication)

프로세스 간 통신 방법입니다.

| 방법 | 설명 | 특징 |
|------|------|------|
| **파이프** | 단방향 데이터 흐름 | 부모-자식 간, 익명/명명 |
| **메시지 큐** | 메시지 단위 송수신 | 비동기, 커널 관리 |
| **공유 메모리** | 메모리 영역 공유 | 가장 빠름, 동기화 필요 |
| **소켓** | 네트워크 통신 | 다른 시스템 간 통신 가능 |
| **시그널** | 비동기 알림 | 인터럽트 처리 |

공유 메모리는 가장 빠르지만 동기화를 직접 구현해야 하고, 메시지 전달 방식은 동기화가 내장되어 있어 안전합니다.

## 면접 예상 질문

**Q. 프로세스와 스레드의 차이?**

프로세스는 실행 중인 프로그램으로 독립적인 메모리 공간(Code, Data, Heap, Stack)을 가집니다. 스레드는 프로세스 내 실행 단위로 Code, Data, Heap을 공유하고 Stack만 독립적입니다. 스레드는 생성 비용과 컨텍스트 스위칭 비용이 낮지만, 공유 자원 동기화가 필요합니다.

**Q. 컨텍스트 스위칭이란?**

CPU가 현재 작업에서 다른 작업으로 전환할 때 상태를 저장하고 복원하는 과정입니다. 프로세스 스위칭은 메모리 주소 공간 전환(TLB 플러시 등)이 필요해 비용이 높고, 스레드 스위칭은 같은 주소 공간을 공유하므로 비용이 낮습니다.

**Q. 멀티프로세스 vs 멀티스레드?**

멀티프로세스는 독립적이라 안정적이지만 메모리 사용량이 많고 IPC 오버헤드가 있습니다. 멀티스레드는 메모리를 공유하여 효율적이지만 동기화가 필요하고 한 스레드 오류가 전체에 영향을 줍니다. 안정성이 중요하면 멀티프로세스, 성능과 자원 효율이 중요하면 멀티스레드를 선택합니다.

**Q. 교착 상태(Deadlock)란?**

두 개 이상의 프로세스/스레드가 서로 상대방이 가진 자원을 기다리며 무한히 대기하는 상황입니다. 상호 배제, 점유 대기, 비선점, 순환 대기 4가지 조건이 모두 만족할 때 발생합니다. 예방(조건 제거), 회피(은행원 알고리즘), 탐지 및 복구 방법이 있습니다.

**Q. 뮤텍스와 세마포어의 차이?**

뮤텍스는 임계 영역에 하나의 스레드만 진입할 수 있는 이진 잠금입니다. 세마포어는 카운터 기반으로 지정된 수만큼 동시 접근을 허용합니다. 뮤텍스는 소유권 개념이 있어 잠근 스레드만 해제할 수 있지만, 세마포어는 다른 스레드가 해제할 수 있습니다.

**Q. CPU 스케줄링 알고리즘?**

FCFS(선입선출), SJF(최단 작업 우선), Round Robin(시간 할당량 순환), Priority(우선순위) 등이 있습니다. Round Robin은 시분할 시스템에서 사용되며, Priority는 기아 문제를 에이징으로 해결합니다.

**Q. IPC 방법들?**

파이프(단방향), 메시지 큐(비동기 메시지), 공유 메모리(가장 빠름, 동기화 필요), 소켓(네트워크 통신), 시그널(비동기 알림) 등이 있습니다. 공유 메모리가 가장 빠르지만 동기화를 직접 구현해야 합니다.
