# 해시 테이블 (Hash Table)

## 해시 테이블이란?

**키(Key)를 해시 함수로 변환하여 값(Value)을 저장하고 조회하는 자료구조**입니다. 평균 O(1) 시간복잡도로 삽입, 삭제, 검색이 가능합니다.

```
Key: "apple"
         │
         ▼
    Hash Function
    hash("apple") = 3
         │
         ▼
┌───┬───┬───┬───────────┬───┬───┐
│ 0 │ 1 │ 2 │     3     │ 4 │ 5 │  ← 버킷/슬롯 배열
└───┴───┴───┴───────────┴───┴───┘
                  │
                  ▼
            ("apple", 100)
```

**구성 요소:**
- **해시 함수 (Hash Function)**: 키를 배열 인덱스로 변환
- **버킷 (Bucket)**: 데이터를 저장하는 배열의 각 슬롯
- **키-값 쌍**: 실제 저장되는 데이터

---

## 해시 함수 (Hash Function)

**임의의 크기의 데이터를 고정된 크기의 값으로 매핑**하는 함수입니다.

```
hash(key) → index (0 ~ 배열크기-1)

예시:
hash("apple") = 문자열을 숫자로 변환 → 배열 크기로 나머지 연산
             = (97+112+112+108+101) % 10 = 530 % 10 = 0
```

**좋은 해시 함수의 조건:**

| 조건 | 설명 |
|------|------|
| **결정적** | 같은 입력은 항상 같은 출력 |
| **균등 분포** | 해시값이 고르게 분포 (충돌 최소화) |
| **빠른 계산** | O(1) 또는 O(키 길이) |
| **눈사태 효과** | 입력이 조금 바뀌면 출력이 크게 변함 |

**일반적인 해시 함수:**

```c
// 나눗셈법 (Division Method)
hash(key) = key % table_size

// 곱셈법 (Multiplication Method)
hash(key) = floor(table_size * (key * A % 1))  // A는 0~1 사이 상수

// 문자열 해시 (다항식 해시)
hash(s) = (s[0]*p^(n-1) + s[1]*p^(n-2) + ... + s[n-1]) % m
```

---

## 시간복잡도

| 연산 | 평균 | 최악 |
|------|------|------|
| 삽입 | O(1) | O(n) |
| 삭제 | O(1) | O(n) |
| 검색 | O(1) | O(n) |

최악의 경우는 모든 키가 같은 인덱스로 해시되어 **충돌이 집중**될 때 발생합니다.

---

## 해시 충돌 (Hash Collision)

**서로 다른 키가 같은 해시값(인덱스)을 가지는 경우**입니다.

```
hash("apple") = 3
hash("grape") = 3  ← 충돌!

키의 개수는 무한하지만, 버킷 수는 유한하므로 충돌은 필연적입니다.
(비둘기집 원리)
```

충돌 해결 방법은 크게 **체이닝**과 **개방 주소법**으로 나뉩니다.

---

## 충돌 해결 1: 체이닝 (Chaining)

**같은 인덱스에 여러 데이터를 연결 리스트로 저장**합니다.

```
Index 0: NULL
Index 1: ("cat", 10) → ("dog", 20) → NULL
Index 2: ("bird", 30) → NULL
Index 3: ("apple", 100) → ("grape", 50) → ("melon", 70) → NULL
Index 4: NULL
```

**삽입:**
```
1. hash(key)로 인덱스 계산
2. 해당 인덱스의 연결 리스트에 (key, value) 추가
```

**검색:**
```
1. hash(key)로 인덱스 계산
2. 연결 리스트 순회하며 key 일치 여부 확인
```

**삭제:**
```
1. hash(key)로 인덱스 계산
2. 연결 리스트에서 해당 노드 제거
```

**장점:**
- 구현이 간단
- 삭제가 쉬움
- 테이블 크기보다 많은 데이터 저장 가능

**단점:**
- 연결 리스트 오버헤드 (포인터 메모리)
- 캐시 효율 낮음 (메모리 비연속)
- 최악의 경우 O(n) (모든 키가 한 버킷에)

**개선: 연결 리스트 대신 트리 사용**

Java HashMap은 버킷당 노드가 8개 이상이면 연결 리스트를 **레드-블랙 트리**로 변환합니다. 최악의 검색이 O(n)에서 O(log n)으로 개선됩니다.

## 충돌 해결 2: 개방 주소법 (Open Addressing)

**충돌 시 다른 빈 버킷을 찾아 저장**합니다. 모든 데이터가 테이블 내부에 저장됩니다.

### 선형 탐사 (Linear Probing)

충돌 시 **순차적으로 다음 버킷**을 확인합니다.

```
h(key, i) = (hash(key) + i) % table_size
(i = 0, 1, 2, 3, ...)

예시: 테이블 크기 7, hash(key) = key % 7

삽입 순서: 50, 700, 76, 85, 92, 73

50:  50 % 7 = 1  → Index 1
700: 700 % 7 = 0 → Index 0
76:  76 % 7 = 6  → Index 6
85:  85 % 7 = 1  → 충돌! → Index 2
92:  92 % 7 = 1  → 충돌! → 2도 충돌! → Index 3
73:  73 % 7 = 3  → 충돌! → Index 4

┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│  0  │  1  │  2  │  3  │  4  │  5  │  6  │
├─────┼─────┼─────┼─────┼─────┼─────┼─────┤
│ 700 │  50 │  85 │  92 │  73 │     │  76 │
└─────┴─────┴─────┴─────┴─────┴─────┴─────┘
```

**문제: 1차 군집화 (Primary Clustering)**

충돌이 발생한 위치 주변으로 데이터가 모여 **연속된 클러스터**가 형성됩니다. 클러스터가 커질수록 충돌 확률이 높아집니다.

```
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ XXX │ XXX │ XXX │ XXX │ XXX │     │     │
└─────┴─────┴─────┴─────┴─────┴─────┴─────┘
      ↑ 클러스터 (새 데이터가 여기 들어올 확률 높음)
```

### 이차 탐사 (Quadratic Probing)

충돌 시 **제곱 간격으로 탐사**합니다.

```
h(key, i) = (hash(key) + i²) % table_size
(i = 0, 1, 2, 3, ...)

탐사 순서: +0, +1, +4, +9, +16, ...
```

1차 군집화는 완화되지만, **2차 군집화**가 발생할 수 있습니다 (같은 해시값을 가진 키들이 같은 탐사 순서를 따름).

### 이중 해싱 (Double Hashing)

**두 번째 해시 함수**로 탐사 간격을 결정합니다.

```
h(key, i) = (hash1(key) + i * hash2(key)) % table_size

hash1: 첫 위치 결정
hash2: 탐사 간격 결정 (키마다 다른 간격)

예시:
hash1(key) = key % 7
hash2(key) = 1 + (key % 5)  // 0이 되면 안 됨
```

키마다 탐사 순서가 달라져 군집화 문제를 효과적으로 해결합니다.

### 개방 주소법에서의 삭제

단순히 삭제하면 검색 경로가 끊어집니다.

```
삽입: 50(→1), 85(→1→2)

검색 85: hash(85)=1 → 50 있음, 85 아님 → 2 확인 → 85 발견!

만약 50을 삭제하면?
검색 85: hash(85)=1 → 비어있음 → "85 없음" (오류!)
```

**해결: 삭제 표시 (Tombstone)**

삭제된 위치에 특수 마커를 남겨 탐사를 계속하게 합니다.

```
┌─────┬───────────┬─────┬─────┐
│  0  │     1     │  2  │  3  │
├─────┼───────────┼─────┼─────┤
│ 700 │ DELETED   │  85 │  92 │
└─────┴───────────┴─────┴─────┘

검색 85: 1은 DELETED → 계속 탐사 → 2에서 발견
```

---

## 체이닝 vs 개방 주소법

| 구분 | 체이닝 | 개방 주소법 |
|------|--------|------------|
| **저장 위치** | 테이블 외부 (연결 리스트) | 테이블 내부 |
| **메모리** | 포인터 오버헤드 | 추가 메모리 없음 |
| **캐시 효율** | 낮음 | 높음 |
| **로드 팩터** | 1 초과 가능 | 1 미만 유지 |
| **삭제** | 간단 | Tombstone 필요 |
| **군집화** | 없음 | 발생 가능 |
| **구현** | 간단 | 복잡 |

## 로드 팩터와 리해싱

**로드 팩터 (Load Factor):**

```
α = n / m

n: 저장된 데이터 수
m: 버킷 수 (테이블 크기)

α가 클수록 충돌 확률 증가
```

| 방식 | 권장 로드 팩터 |
|------|---------------|
| 체이닝 | 1.0 이하 |
| 개방 주소법 | 0.5 ~ 0.7 이하 |

**리해싱 (Rehashing):**

로드 팩터가 임계값을 초과하면 **테이블 크기를 늘리고 모든 데이터를 다시 해싱**합니다.

```
1. 새 테이블 생성 (보통 2배 크기)
2. 기존 모든 데이터에 대해:
   - 새 해시값 계산
   - 새 테이블에 삽입
3. 기존 테이블 해제

시간복잡도: O(n)
평균적으로 분할 상환하면 삽입은 여전히 O(1)
```

## 해시 테이블 사용 예시

**빈도 수 계산:**

```python
def count_frequency(arr):
    freq = {}
    for item in arr:
        freq[item] = freq.get(item, 0) + 1
    return freq

# O(n) 시간복잡도
```

**두 수의 합 (Two Sum):**

```python
def two_sum(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return []

# O(n) vs 브루트포스 O(n²)
```

**중복 확인:**

```python
def has_duplicate(arr):
    seen = set()
    for item in arr:
        if item in seen:
            return True
        seen.add(item)
    return False

# O(n) 시간, O(n) 공간
```

## 면접 예상 질문

**Q. 해시 테이블이란?**

키를 해시 함수로 변환하여 배열 인덱스에 값을 저장하는 자료구조입니다. 평균 O(1)로 삽입, 삭제, 검색이 가능합니다. 최악의 경우(모든 키가 충돌) O(n)이 됩니다.

**Q. 해시 충돌이란? 왜 발생하나요?**

서로 다른 키가 같은 해시값을 가지는 경우입니다. 키의 개수는 무한하지만 버킷 수는 유한하므로 비둘기집 원리에 의해 충돌은 필연적입니다.

**Q. 충돌 해결 방법?**

체이닝과 개방 주소법이 있습니다. 체이닝은 같은 인덱스에 연결 리스트로 저장합니다. 개방 주소법은 충돌 시 다른 빈 버킷을 찾으며, 선형 탐사, 이차 탐사, 이중 해싱 방식이 있습니다.

**Q. 선형 탐사의 문제점?**

1차 군집화가 발생합니다. 충돌 위치 주변으로 데이터가 모여 연속된 클러스터가 형성되고, 클러스터가 커질수록 충돌 확률이 높아집니다. 이중 해싱으로 해결할 수 있습니다.

**Q. 개방 주소법에서 삭제 시 주의점?**

단순 삭제하면 검색 경로가 끊어집니다. 삭제 위치에 Tombstone 마커를 남겨 탐사를 계속할 수 있게 해야 합니다.

**Q. 로드 팩터란?**

저장된 데이터 수를 버킷 수로 나눈 값입니다. 로드 팩터가 높으면 충돌 확률이 증가합니다. 임계값을 초과하면 리해싱으로 테이블을 확장합니다. 개방 주소법은 0.7 이하, 체이닝은 1.0 이하를 권장합니다.

**Q. 해시 테이블의 시간복잡도가 O(n)이 되는 경우?**

모든 키가 같은 인덱스로 해시되어 한 버킷에 집중될 때입니다. 체이닝이면 연결 리스트 순회 O(n), 개방 주소법이면 전체 테이블 탐사 O(n)이 됩니다. 좋은 해시 함수로 균등 분포를 유지하면 방지할 수 있습니다.
