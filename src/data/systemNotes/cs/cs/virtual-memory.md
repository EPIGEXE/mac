# 가상 메모리

## 가상 메모리란?

**물리 메모리(RAM)보다 큰 주소 공간을 프로세스에 제공하는 메모리 관리 기법**입니다. 각 프로세스는 자신만의 연속된 가상 주소 공간을 가지며, 운영체제와 하드웨어(MMU)가 이를 실제 물리 메모리에 매핑합니다.

```
┌─────────────────┐     ┌─────────────────┐
│  Process A      │     │  Physical       │
│  Virtual Memory │     │  Memory (RAM)   │
│  ┌───────────┐  │     │  ┌───────────┐  │
│  │ 0x0000    │──┼──┐  │  │ Frame 0   │  │
│  │ 0x1000    │──┼──┼──┼─►│ Frame 1   │  │
│  │ 0x2000    │──┼──┼──┼─►│ Frame 2   │  │
│  │ ...       │  │  │  │  │ ...       │  │
│  │ 0xFFFF    │  │  │  │  │ Frame N   │  │
│  └───────────┘  │  │  │  └───────────┘  │
└─────────────────┘  │  └─────────────────┘
                     │
┌─────────────────┐  │  ┌─────────────────┐
│  Process B      │  │  │  Disk (Swap)    │
│  Virtual Memory │  │  │  ┌───────────┐  │
│  ┌───────────┐  │  └──┼─►│ Swap 영역  │  │
│  │ 0x0000    │──┼─────┼─►│           │  │
│  │ ...       │  │     │  └───────────┘  │
│  └───────────┘  │     └─────────────────┘
└─────────────────┘
```

**핵심 개념:**
- **가상 주소**: 프로세스가 사용하는 논리적 주소
- **물리 주소**: 실제 RAM의 주소
- **주소 변환**: MMU(Memory Management Unit)가 가상 → 물리 주소 변환

---

## 가상 메모리의 장점

**1. 메모리 추상화**

각 프로세스는 전체 메모리를 독점하는 것처럼 사용할 수 있습니다. 실제 물리 메모리 배치를 신경 쓸 필요가 없습니다.

**2. 메모리 보호**

프로세스마다 독립된 주소 공간을 가져 다른 프로세스의 메모리에 접근할 수 없습니다.

**3. 물리 메모리보다 큰 공간 사용**

당장 필요하지 않은 부분은 디스크(스왑 영역)에 저장하고, 필요할 때 메모리로 가져옵니다.

**4. 메모리 공유**

여러 프로세스가 같은 물리 메모리를 공유할 수 있습니다 (공유 라이브러리, IPC 등).

---

## 페이징 (Paging)

**가상 메모리를 고정 크기의 페이지(Page)로, 물리 메모리를 같은 크기의 프레임(Frame)으로 나누어 관리**하는 기법입니다.

```
가상 메모리              물리 메모리
┌─────────┐             ┌─────────┐
│ Page 0  │────────────►│ Frame 3 │
├─────────┤             ├─────────┤
│ Page 1  │──┐          │ Frame 0 │◄──┐
├─────────┤  │          ├─────────┤   │
│ Page 2  │──┼─────────►│ Frame 1 │   │
├─────────┤  │          ├─────────┤   │
│ Page 3  │  └─────────►│ Frame 5 │   │
├─────────┤             ├─────────┤   │
│ Page 4  │─────────────┼─────────┼───┘
└─────────┘             │ Frame 2 │
                        ├─────────┤
    페이지 크기          │ Frame 4 │
    = 프레임 크기        └─────────┘
    (보통 4KB)
```

**페이지 테이블 (Page Table):**

가상 페이지 번호를 물리 프레임 번호로 매핑하는 테이블입니다. 프로세스마다 하나씩 존재합니다.

```
Page Table (Process A)
┌─────────┬─────────┬───────┬───────┬───────┐
│ Page #  │ Frame # │ Valid │ Dirty │ Perm  │
├─────────┼─────────┼───────┼───────┼───────┤
│    0    │    3    │   1   │   0   │  RW   │
│    1    │    5    │   1   │   1   │  RW   │
│    2    │    -    │   0   │   -   │   -   │ ← 메모리에 없음
│    3    │    1    │   1   │   0   │   R   │
└─────────┴─────────┴───────┴───────┴───────┘
```

- **Valid bit**: 해당 페이지가 물리 메모리에 있는지 (0이면 페이지 폴트)
- **Dirty bit**: 페이지가 수정되었는지 (스왑 아웃 시 디스크 쓰기 필요 여부)
- **Permission**: 읽기/쓰기/실행 권한

**주소 변환 과정:**

```
가상 주소: [페이지 번호 | 오프셋]
              ↓
         페이지 테이블 조회
              ↓
물리 주소: [프레임 번호 | 오프셋]

예: 페이지 크기 4KB, 가상 주소 0x00002A3C
- 페이지 번호: 0x00002 (상위 비트)
- 오프셋: 0xA3C (하위 12비트)
- 페이지 테이블에서 페이지 2의 프레임 번호 조회
- 물리 주소: [프레임 번호 | 0xA3C]
```

## 페이지 폴트 (Page Fault)

**접근하려는 페이지가 물리 메모리에 없을 때 발생하는 인터럽트**입니다.

```
1. CPU가 가상 주소 접근
2. MMU가 페이지 테이블 확인 → Valid bit = 0
3. 페이지 폴트 발생 (인터럽트)
4. OS가 디스크에서 해당 페이지를 메모리로 로드
5. 페이지 테이블 업데이트 (Valid = 1, 프레임 번호 기록)
6. 중단된 명령 재실행
```

**빈 프레임이 없을 때:**
- 기존 페이지 중 하나를 스왑 아웃 (디스크로 내보냄)
- Dirty bit가 1이면 디스크에 쓰기, 0이면 그냥 버림
- 페이지 교체 알고리즘으로 희생 페이지 선택

---

## 페이지 교체 알고리즘

물리 메모리가 가득 찼을 때 어떤 페이지를 내보낼지 결정합니다.

**1. FIFO (First In First Out)**

가장 먼저 들어온 페이지를 교체합니다.

```
참조 순서: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 (프레임 3개)

[1]       → [1,2]     → [1,2,3]   → [4,2,3]   → [4,1,3]   → ...
                                   (1 교체)    (2 교체)
```

- 단순하지만 **Belady's Anomaly** 발생 가능 (프레임 늘려도 폴트 증가)

**2. LRU (Least Recently Used)**

가장 오래 사용되지 않은 페이지를 교체합니다.

```
참조 순서: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5

시간 기준으로 가장 오래 전에 사용된 페이지 교체
```

- 과거 기록이 미래 예측에 좋은 지표
- 구현 비용 높음 (타임스탬프 또는 스택 필요)

**3. LFU (Least Frequently Used)**

사용 빈도가 가장 낮은 페이지를 교체합니다.

**4. Optimal (OPT)**

앞으로 가장 오랫동안 사용되지 않을 페이지를 교체합니다. 이론적으로 최적이지만 미래를 알 수 없어 실제 구현 불가능합니다. 다른 알고리즘의 성능 비교 기준으로 사용됩니다.

**5. Clock (Second Chance)**

FIFO의 변형으로, 참조 비트를 사용합니다. 교체 대상이 최근 참조되었으면 한 번 더 기회를 줍니다.

```
시계 바늘이 돌면서:
- 참조 비트 1 → 0으로 바꾸고 넘어감 (한 번 더 기회)
- 참조 비트 0 → 교체
```

## TLB (Translation Lookaside Buffer)

**페이지 테이블 조회를 빠르게 하기 위한 캐시**입니다. 최근 사용된 페이지-프레임 매핑을 저장합니다.

```
주소 변환 과정:

CPU ──► TLB 확인 ──► Hit → 바로 물리 주소
              │
              └──► Miss → 페이지 테이블 조회 → TLB 업데이트
```

- **TLB Hit**: TLB에서 바로 변환 (매우 빠름)
- **TLB Miss**: 페이지 테이블 조회 필요 (느림)
- 컨텍스트 스위칭 시 TLB 플러시 (다른 프로세스의 매핑이므로)

## 세그멘테이션 (Segmentation)

**프로그램을 논리적 단위(세그먼트)로 나누어 관리**하는 기법입니다. 코드, 데이터, 스택 등 의미 있는 단위로 분리합니다.

```
프로세스 주소 공간

┌─────────────────┐
│   Code Segment  │ ← 크기: 10KB
├─────────────────┤
│   Data Segment  │ ← 크기: 5KB
├─────────────────┤
│   Stack Segment │ ← 크기: 8KB
├─────────────────┤
│   Heap Segment  │ ← 크기: 20KB
└─────────────────┘

각 세그먼트는 가변 크기
```

**세그먼트 테이블:**

```
Segment Table
┌─────────┬──────────┬────────┬───────┐
│ Segment │   Base   │ Limit  │ Perm  │
├─────────┼──────────┼────────┼───────┤
│  Code   │ 0x10000  │ 10KB   │  RX   │
│  Data   │ 0x20000  │  5KB   │  RW   │
│  Stack  │ 0x30000  │  8KB   │  RW   │
│  Heap   │ 0x40000  │ 20KB   │  RW   │
└─────────┴──────────┴────────┴───────┘

- Base: 세그먼트 시작 물리 주소
- Limit: 세그먼트 크기 (경계 검사용)
```

**주소 변환:**

```
가상 주소: [세그먼트 번호 | 오프셋]

1. 세그먼트 테이블에서 Base, Limit 조회
2. 오프셋 < Limit 인지 확인 (아니면 세그멘테이션 폴트)
3. 물리 주소 = Base + 오프셋
```

## 페이징 vs 세그멘테이션

| 구분 | 페이징 | 세그멘테이션 |
|------|--------|-------------|
| **분할 단위** | 고정 크기 (페이지) | 가변 크기 (논리적 단위) |
| **관점** | 물리적 (OS 관점) | 논리적 (프로그래머 관점) |
| **외부 단편화** | 없음 | 있음 |
| **내부 단편화** | 있음 (마지막 페이지) | 없음 |
| **주소 변환** | 페이지 테이블 | 세그먼트 테이블 |
| **메모리 보호** | 페이지 단위 | 세그먼트 단위 (논리적) |
| **공유** | 페이지 단위 | 세그먼트 단위 (의미 있는 공유) |

**단편화:**

```
외부 단편화 (External Fragmentation):
- 세그멘테이션에서 발생
- 메모리에 빈 공간이 흩어져 있어 큰 세그먼트 할당 불가

┌────┐┌──┐┌────┐┌──┐┌────┐
│사용││빈││사용││빈││사용│
└────┘└──┘└────┘└──┘└────┘
         ↑
    합치면 충분하지만 연속되지 않아 할당 불가

내부 단편화 (Internal Fragmentation):
- 페이징에서 발생
- 페이지 내부에 사용되지 않는 공간

페이지 크기: 4KB
실제 데이터: 2.5KB
→ 1.5KB 낭비
```

## 페이지드 세그멘테이션 (Paged Segmentation)

**세그멘테이션과 페이징을 결합**한 방식입니다. 세그먼트를 다시 페이지로 나눕니다.

```
가상 주소: [세그먼트 번호 | 페이지 번호 | 오프셋]

1. 세그먼트 테이블에서 해당 세그먼트의 페이지 테이블 찾기
2. 페이지 테이블에서 프레임 번호 찾기
3. 물리 주소 = 프레임 번호 + 오프셋
```

- 논리적 분할의 장점 (세그멘테이션)
- 외부 단편화 제거 (페이징)
- 현대 OS는 주로 **순수 페이징** 또는 **페이지드 세그멘테이션** 사용

## 스래싱 (Thrashing)

**페이지 폴트가 과도하게 발생하여 실제 작업보다 페이지 교체에 더 많은 시간을 소비하는 현상**입니다.

```
원인:
- 너무 많은 프로세스가 메모리를 나눠 사용
- 각 프로세스의 프레임 수 부족
- 페이지 폴트 → 스왑 → 또 폴트 → 반복

                  CPU 사용률
                       │
                       │    /\
                       │   /  \
                       │  /    \
                       │ /      \_____
                       │/
                       └───────────────
                             멀티프로그래밍 정도
                                  ↑
                              스래싱 발생
```

**해결 방법:**
- 프로세스 수 줄이기 (스왑 아웃)
- 워킹셋(Working Set) 모델: 프로세스별 최소 프레임 보장
- PFF(Page Fault Frequency): 폴트율 기반 프레임 할당 조절

## 면접 예상 질문

**Q. 가상 메모리란?**

물리 메모리보다 큰 주소 공간을 프로세스에 제공하는 메모리 관리 기법입니다. 프로세스마다 독립된 가상 주소 공간을 가지고, MMU가 가상 주소를 물리 주소로 변환합니다. 메모리 보호, 추상화, 공유, 스왑을 통한 확장이 가능합니다.

**Q. 페이징과 세그멘테이션의 차이?**

페이징은 고정 크기 페이지로 나누어 외부 단편화가 없지만 내부 단편화가 있습니다. 세그멘테이션은 가변 크기의 논리적 단위로 나누어 내부 단편화는 없지만 외부 단편화가 있습니다. 현대 OS는 주로 페이징을 사용합니다.

**Q. 페이지 폴트란?**

접근하려는 페이지가 물리 메모리에 없을 때 발생하는 인터럽트입니다. OS가 디스크에서 해당 페이지를 메모리로 로드하고 페이지 테이블을 업데이트한 후 명령을 재실행합니다. 빈 프레임이 없으면 페이지 교체 알고리즘으로 희생 페이지를 선택합니다.

**Q. LRU 알고리즘이란?**

가장 오래 사용되지 않은 페이지를 교체하는 알고리즘입니다. 과거 사용 패턴이 미래를 잘 예측한다는 지역성 원리에 기반합니다. 최적에 가까운 성능이지만 구현 비용이 높아 근사 알고리즘(Clock)을 사용하기도 합니다.

**Q. TLB란?**

페이지 테이블 조회를 빠르게 하기 위한 캐시입니다. 최근 사용된 페이지-프레임 매핑을 저장하여 TLB Hit 시 바로 주소 변환이 가능합니다. 컨텍스트 스위칭 시 다른 프로세스의 매핑이므로 플러시됩니다.

**Q. 스래싱이란?**

페이지 폴트가 과도하게 발생하여 실제 작업보다 페이지 교체에 더 많은 시간을 소비하는 현상입니다. 너무 많은 프로세스가 메모리를 나눠 써서 각자 프레임이 부족할 때 발생합니다. 워킹셋 모델로 프로세스별 최소 프레임을 보장하여 해결합니다.
